## RF-005 | Ventana emergente  

Con base a lo obtenido de RF-004, el sistema arroja una ventana emergente con el mensaje "Número telefónico no registrado" y lo manda a la fase de registro de datos 

## Objetivo 

El sistema permite la notificación del estatus no registro mediante una ventana emergente con el mensaje número telefónico no registrado y lo manda al formulario del RF-006 

## Alcance  

Despliegue de elementos visuales (popups) con el mensaje no registrado y lo manda hacia la fase de registro. 

## Precondición 

El usuario ingresa su número telefónico que no se encuentra registrado previamente en el sistema 

## Postcondición 

El usuario es transferido al formulario del RF-006 conservando su número telefónico. Para el inicio de registros de datos  

## Flujo principal 

El sistema arroja una ventana emergente indicando que el número telefónico no está registrado 

El concursante presiona la opción “Ok” 

El sistema permite al usuario acceder a la fase de registro de datos. 

## Flujos Alternos  

A1. Usuario Ya Registrado: 

El sistema identifica que el número telefónico ya existe en la base de datos. 

El sistema muestra el nombre del participante y su número. 

El sistema omite la captura de datos personales (RF-005) y redirige directamente al registro de ticket (RF-006). 

A2. Formato de Teléfono Inválido: 

El concursante ingresa un número con menos o más de 10 dígitos o caracteres alfanuméricos. 

El sistema muestra el mensaje de error: "Por favor ingresa un número telefónico válido a 10 dígitos". 

El sistema permanece en la misma pantalla hasta corregir el dato. 

## Trazabilidad 

RF-001: El flujo de verificación telefónica es la acción inmediata que se desencadena cuando el concursante presiona el botón principal de "Comenzar" en la Pantalla de Inicio. 

RF-005: Determina el registro de nuevos usuarios; si la consulta en la base de datos confirma que el número no existe, el sistema habilita la captura de datos personales y la aceptación del Aviso de Privacidad. 

RF-006: Permite agilizar la experiencia a los concursantes recurrentes; si la consulta confirma que el número ya está registrado, el sistema omite el paso de registro de datos y los redirige directamente a la carga del ticket de compra. 

RF-008: Garantiza que el número telefónico validado en este paso sea exactamente el mismo al que se enviará automáticamente el mensaje SMS con el folio de participación por si resulta ganador. 

RF-009: Establece la clave de identificación del concursante en caso de fallo en la trivia, permitiéndole reutilizar su mismo número telefónico verificado para reintentar la dinámica adjuntando un nuevo ticket. 

## Justificación y métrica 

Justificación: En caso de los usuarios ya registrados, agilizar el proceso de inicio de sesión para minimizar el tiempo de registro del ticket, de esta forma maximizamos la eficiencia de tiempo que tienen los clientes para subir más tickets 

Métrica de Tiempo: Reducir el tiempo de inicio de flujo de 1.5 minutos a menos de 10 segundos para usuarios recurrentes. 

 

## RF-006 | Ventana emergente  

El sistema permite capturar los datos personales del concursante (nombre, primer apellido, segundo apellido, teléfono, correo electrónico y domicilio). 

## Objetivo 

Permitir al concursante registrar sus datos personales de manera segura y estandarizada. 

## Alcance 

El despliegue y validación del formulario de registro exclusivamente para usuarios nuevos (nombre, primer apellido, segundo apellido, teléfono, correo electrónico y domicilio). 

## Actores 

El Concursante (Cliente que participa en la dinámica). 

## Precondiciones 

El concursante debió haber entrado a la página de inicio y comenzar la fase de registro como usuario nuevo 

## Postcondiciones 

El concursante queda registrado con sus datos personales y comienza la fase de "Datos de la compra" con la elección de la sucursal y subida del ticket. 

## Flujo Principal 

1. El concursante ingresa su nombre. 

2. El concursante ingresa su primer apellido. 

3. El concursante ingresa su segundo apellido. 

4. El concursante ingresa su correo. 

5. El concursante ingresa su número. 

6. El concursante ingresa su domicilio. 

## Flujos Alternos 

A1. El concursante no ingresa su nombre 

El sistema detecta que el campo del nombre se encuentra vacío 

El sistema muestra el mensaje "Campo obligatorio" en la sección "Nombre" 

A2. El concursante no ingresa su Primer apellido 

El sistema detecta que el campo del apellido se encuentra vacío 

El sistema muestra el mensaje "Campo obligatorio" en la sección "Primer apellido" 

A3. El concursante no ingresa su Segundo apellido 

El sistema detecta que el campo del apellido se encuentra vacío 

El sistema muestra el mensaje "Campo obligatorio" en la sección "Segundo apellido" 

A4. El concursante no ingresa su correo de forma "nombre@correo.com" 

El sistema detecta que el campo del correo se no se encuentra en el formato establecido 

El sistema muestra el mensaje "Campo obligatorio" en la sección "Correo electrónico" 

A5. El concursante no ingresa su Número o lo captura mal. 

El sistema detecta que el campo del número se encuentra vacío o ingresa un carácter no numérico. 

El sistema muestra el mensaje "Campo obligatorio" en la sección "Número telefónico" 

A6. El concursante no ingresa su Domicilio. 

El sistema detecta que el campo del número se encuentra vacío o ingresa un carácter no numérico. 

El sistema muestra el mensaje "Campo obligatorio" en la sección "Domicilio” 

## Trazabilidad 

RF-004: Es un requisito previo indispensable para acceder a la fase de captura de datos. 

RF-009: RF-006 actúa como requisito previo para acceder. 

RF-010: RF-006 actúa como requisito previo para acceder. 

RF-011: RF-006 actúa como requisito previo para acceder. 

RF-014: RF-006 actúa como requisito para el folio una vez terminada la trivia.

## Justificación y Métricas de Campo 

Punto de campo: El concursante ingresa sus datos para que posteriormente si gana un premio por la trivia, entonces pueda ser contactado. 

Métrica: 4 de cada 5 personas de entre 40 años a 60 años y 9 de cada 10 personas de entre 20 a 30 años puedan registrar sus datos correctamente.
