# RF-015 | Trivia

El sistema muestra al concursante, cuando no responde correctamente todas las preguntas de la trivia, una pantalla con un mensaje de agradecimiento, la indicación de que aún puede volver a intentarlo con el mismo número telefónico que registró y un botón "Volver a participar".

## Resumen del Requisito

| Campo | Detalles |
| :--- | :--- |
| **Objetivo** | Que el concursante sepa que no respondió correctamente todas las preguntas de la trivia y que aún puede volver a intentarlo, para que siga participando. |
| **Alcance** | Se limita a mostrar la pantalla con el mensaje "No se completó el registro" y el botón de "Reintentar". |
| **Actores** | El Concursante (Cliente que participa en la dinámica). |
| **Precondiciones** | El concursante participó en la trivia y respondió una pregunta de forma errónea. |
| **Postcondiciones** | El concursante puede iniciar un nuevo intento de participación con el mismo número telefónico que registró. |
| **Trazabilidad** | **RF-013:** Funciona como requisito obligatorio para mostrar la pantalla de trivia fallida. |

---

## Flujo Principal

1. El concursante termina de responder las preguntas de la trivia y al menos una de sus respuestas es incorrecta.
2. El sistema muestra la pantalla **"Mejor suerte la próxima"**, con el ícono de error, el mensaje *"¡Gracias por participar!"* y la indicación de que no respondió correctamente todas las preguntas, pero aún puede volver a intentarlo con el mismo número telefónico que registró.
3. El concursante presiona el botón **"Volver a participar"**.
4. El sistema lo dirige a la pantalla de ingreso del número telefónico.

---

## Flujos Alternos

* No hay.

---

## Justificación y Métrica

* **Justificación:** Se justifica por ser un aviso necesario cuando el concursante ya no puede continuar el proceso para asegurar que el concursante pueda ser redirigido a realizar un próximo nuevo intento.
* **Métrica:** Lograr que el 100% de los concursantes que fallan la trivia identifiquen cómo volver a participar y presionen "Volver a participar" completamente solos, sin pedir ayuda.

# RNF - 001 | Portabilidad

El sistema debe contar con un diseño responsivo que adapte su interfaz automáticamente evitando la distorsión visual en las pantallas de dispositivos móviles y tabletas.

## Resumen del Requisito No Funcional

| Campo | Detalles |
| :--- | :--- |
| **Objetivo** | Garantizar que los concursantes puedan registrarse y participar en la trivia desde cualquier dispositivo, con una interfaz sin distorsión. |
| **Alcance** | Está presente en cada etapa del registro (inicio, el registro de datos y la trivia), aplica al registro de participantes. |
| **Actores** | El concursante (cliente que participa en la dinámica). |
| **Trazabilidad** | Este RNF se relaciona con cada etapa del registro (**RF-001** al **RF-011**). |

---

## Criterios de Aceptación

1. La interfaz se adapta automáticamente en anchos de pantalla de **360 px a 1024 px**, sin la intervención del usuario en cada etapa del registro.
2. Textos, botones, campos y mensajes de instrucciones permanecen visibles, sin cortes, legibles y sin superposición en los anchos de pantalla de **360 px a 1024 px** en cada etapa del registro.
3. No existe desplazamiento horizontal en ninguna etapa del registro.
4. El sistema funciona correctamente en las versiones actuales de Chrome, Safari y Firefox.

---

## Método de Justificación

* Pruebas funcionales en dispositivos Android e iOS, utilizando las versiones actuales de Chrome, Firefox y Safari (en el caso de iOS).
* Pruebas con las herramientas de emulación de dispositivos del navegador (DevTools).

---

## Justificación y Métrica

* **Justificación:** Con base en los datos recopilados se concluyó que las personas con celulares más pequeños solían hacer más clics accidentales (debido a no tener un diseño responsivo) que las personas con celulares más grandes, lo que las llevaba a frustrarse porque tenían que volver a comenzar el registro desde cero.
